# Laplace complete capability and flow map

Status: delivery authority projection for the clean replacement implementation.

This document maps the intended Laplace product as one machine. It is derived from the current product requirements, finish-line program, cognition execution architecture, inventor-direct synthesis, and governing whole-product issues. It does not make documentation completion count as product completion. Every capability below remains subject to executable acceptance and the repository's no-private-semantics rule.

## 1. Competitive product thesis

Laplace is intended to replace the conventional transformer-centric AI execution stack with one Unicode-native, content-addressed, persistent computational substrate whose identity, structure, evidence, trust, geometry, execution, cognition, learning, realization, model projection, and receipts remain explicit and interoperable.

The core product invariant is:

```text
exact bytes / events / observations
    -> canonical Unicode-native identity
    -> universal typed AST / Merkle DAG
    -> exact physicality + occurrence / trajectory state
    -> independent evidence / testimony / calculation / geometry / standing planes
    -> immutable recipe compiled to the common ISA
    -> query-relative typed provider selection
    -> bounded filtered set-wise search / fold / guidance update
    -> semantic completion, semantic act, or exact WHY_NOT
    -> realization / effect
    -> witnessed output + provenance + execution receipt
    -> persistent substrate state
    -> future cognition / learning / target compilation / public transports
```

No transport, database adapter, decomposer, domain implementation, model exporter, UI, or compatibility layer may become a second semantic owner.

## 3. One-machine execution flows

### 3.1 Admission / ingest

```text
source bytes/events
 -> identify source authority + release + license + boundary
 -> select grammar/decomposer recipe
 -> exact decode / segmentation / universal AST
 -> BLAKE3 content identity + Merkle subtree reuse
 -> calculate physicality / geometry / trajectory / occurrence state
 -> write immutable structural state
 -> record source/testimony/evidence lineage separately
 -> calculate eligible standing/derived planes separately
 -> close world-admission receipt
 -> activate read/index/perfcache epochs
```

A source-specific parser may implement physical grammar mechanics. It may not create a private semantic identity, trust model, cognition loop, or completion law.

### 3.2 Live conversation

```text
user turn / cross-modal observation
 -> persist exact observation and session occurrence
 -> resolve canonical content/referents/tier
 -> orient discourse state, goal, authority, world, time and obligations
 -> compile finite request/guidance/search program
 -> select independent provider families
      physicality/occurrence
      testimony/facts
      deterministic calculations
      geometry/locality
      standing/trust
 -> push source/context/time/world/tier/dependence filters
 -> form bounded typed frontier
 -> A*/best-first search with exact receipts
 -> fold declared structural + factual + calculated + standing channels
 -> update guidance/deficits/obligations
 -> repeat while finite and unresolved
 -> select semantic act, answer state, effect, or WHY_NOT
 -> realize in requested language/register/modality
 -> witness output, path, evidence roots, resources and effects
 -> append result to persistent discourse for future turns
```

The conversation is therefore not a lookup followed by text generation. It is persistent state transition over the same substrate used by every other capability.

### 3.3 Evidence and correction learning

```text
new observation/testimony/result
 -> preserve immutable source evidence
 -> classify epistemic kind and dependence
 -> compare against existing competing propositions
 -> calculate eligible standing outcome in its declared lane
 -> publish new time-addressable evidence/standing epoch
 -> preserve contradiction rather than overwrite history
 -> future cognition selects the appropriate as-of world/evidence boundary
```

### 3.4 Gödel / skill / habit / muscle-memory loop

```text
repeated problem state
 -> cognition constructs finite program
 -> execute + receipt
 -> witness outcome
 -> compare predicted/actual effect and completion
 -> discover reusable structural/program pattern
 -> verify against independent cases and negative controls
 -> promote as typed recipe/skill only after proof
 -> repeated validated reuse reduces future search
 -> habit/muscle-memory remains a receipted program, never hidden weight authority
```

Self-observation can become future evidence, but it cannot count as independent corroboration of itself.

### 3.5 Chess / domain action

```text
board/game/player/time observation
 -> ordinary canonical identity + physicality/occurrence/evidence
 -> domain calculations (legal moves, Stockfish, Pesto, clocks, historical stats) as declared providers
 -> same cognition request/guidance/search/fold/update loop
 -> semantic act: explain/analyze/move/compare/WHY_NOT
 -> effect if authorized
 -> witness result and outcome
 -> standing/learning may update through declared lanes
```

There is no separate 'chess intelligence' allowed to bypass the general machine.

### 3.6 Target model / AI-map compilation

```text
selected live substrate boundary/epoch
 -> query exact structural/evidence/geometry/standing planes
 -> form target-neutral typed operators
 -> apply declared target architecture mapping recipe
 -> compile Q/K/V/O, positional state, FFN/gates/experts/other tensors as required
 -> serialize target format
 -> emit provenance mapping each target component back to source operators/epochs
 -> optionally round-trip / compare target behavior against Laplace reference behavior
```

The exported model is a view/checkpoint of Laplace state for another runtime; it is not the native semantic authority.

### 3.7 Agentic software-development flow

The earlier Hartonomous objective survives as product capability, but not as the obsolete LangGraph/LLM/storage stack used in early blueprints.

```text
project/repository/world state
 -> persistent exact observations of files/issues/tests/builds/runs/requirements
 -> discourse goal and acceptance predicates
 -> cognition selects research/architecture/code/test/build/docs/deploy semantic acts
 -> tool/effect recipes operate in bounded sandboxes
 -> receipts witness exact changes, tests, failures and outcomes
 -> failed attempts re-enter replayable learning
 -> validated reusable project/program patterns become skills/templates
```

Architect, researcher, developer, QA, build, documentation and deployment roles are views/programs over one machine, not separate hidden agents with private memory or semantics.

### 3.8 Public transport flow

```text
OpenAI / MCP / CLI / web / mobile / document request
 -> transport authentication + entitlement
 -> canonical session/request compiler
 -> same native cognition/realization/effect owner
 -> exact receipt/provenance
 -> transport-specific envelope only
```

A route that works by calling a private SQL query, RAG index, model, keyword router, or endpoint-specific reasoning loop is non-conforming even if its output looks useful.

### 3.9 Federation/entity-world flow

```text
local or remote observation
 -> canonical content identity
 -> explicit source/node/world/audience/authority scope
 -> immutable evidence lineage and time boundary
 -> reconciliation/adjudication without rewriting source testimony
 -> authorized query/cognition over selected world boundary
```

Content equality may cross nodes; private world state, standing, authority and disclosure scopes do not collapse merely because content identities match.

## 4. Internal ownership boundaries

The clean Refactor product is singular **inside this repository**:

```text
identity / Unicode / AST / Merkle
       |
composition / physicality / occurrence / geometry
       |
evidence / testimony / dependence / standing
       |
recipe compiler + generated operation registry + ISA
       |
request compiler / guidance / provider composition / bounded query-search
       |
semantic completion / semantic act
       |
realization / effect
       |
persistent witness / receipt / session state
       |
OpenAI / MCP / CLI / web / model-export / domain transports
```

The legacy `Laplace` repository is not a runtime dependency of this stack. Any later migration is an explicit one-way import/migration process into Refactor's canonical representation, not a permanent bridge.
