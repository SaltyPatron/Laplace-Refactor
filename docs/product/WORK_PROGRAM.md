## Phase 0 — product authority and clean-room foundation

- Establish one repository whose implementation is authored from direct product
  requirements, independent standards, and verified upstream dependency sources.
- Record the invention constitution and clean-room authorship rule.
- Establish requirement identifiers, operational ownership, and bidirectional
  traceability.
- Reject any predecessor implementation as source, schema, build, package, or test
  authority.

Exit: the constitution is represented in machine-readable requirements, every product
requirement has an operational owner, and repository checks prove all implementation
and acceptance evidence belongs to the new product.

## Phase 1 — industrial build and dependency foundation

- Inventory and verify the existing upstream source trees and installed custom stack.
- Keep the pre-framework bootstrap minimal: it may acquire, build, test, and stage
  inert content-addressed packages, but only the execution framework may activate
  packages, initialize product state, or admit loaded runtime objects.
- Select one compatible dependency graph from verified upstream identities and current
  support requirements.
- Lock source, checksums, licenses, patches, features, toolchains, and ABI facts.
- Build PostgreSQL, PostGIS, GDAL, GEOS, PROJ, and the complete native graph on Linux
  and Windows.
- Produce staged dependency packages, symbols, provenance, and SBOMs.
- Establish hermetic configure, build, test, package, and clean commands.

Exit: a clean machine can acquire, verify, build, test, package, install, repeat the
install, and verify the custom dependency runtime from declared inputs.

## Phase 2 — universal execution framework and executable ISA

- Generate the typed module/value/operation registry from one contract; no module may
  add a private dispatcher or independently assign operation or value identifiers.
- Bind every program to one immutable execution context naming source, identity,
  geometry, evidence, firmware, dependency, database, perfcache, numeric, and package
  epochs.
- Implement one canonical vector/set/run batch representation and the common
  decomposer/calculation pipeline that produces it.
- Implement replaceable typed sink/provider interfaces for persistence, perfcache
  generation, derived epochs, result streams, observations, and external effects.
- Implement complete-program preflight, authority/effect admission, cancellation,
  replay, deterministic merge, progress, durable publication, and full receipts.
- Apply one conserved topology/resource grant across native kernels, TBB arenas, MKL
  domains, PostgreSQL workers, managed orchestration, and launched tools.
- Finalize universal value types, C ABI, ISA versioning, encoding, validation,
  execution, error, estimation, and explanation contracts on that framework.
- Generate native, PostgreSQL, SQL, and C# bindings from the same registry and reject
  semantic implementations in an adapter or transport.
- Implement vector-first dispatch, bounded arenas, and SQL program validation,
  explanation, execution, and receipt inspection.

Exit: synthetic modules and the first real proving module execute through the same
registry, context, batch, sink/provider, epoch, resource, receipt, and generated
binding lifecycle; packaged custom PostgreSQL executes those typed native programs;
deliberate framework bypasses and invalid programs fail for their exact expected
reasons.

## Phase 5 — universal query and conversation

- Implement indexed addressing, query/key correlation, value retrieval, traversal,
  selection, composition, and materialization instructions.
- Implement typed neighborhood programs that retain exact structural, occurrence,
  angular, radial, Hilbert, Fréchet, Hausdorff, Karcher-derived, semantic, Glicko-2,

  goal-specific importance and ranking with complete receipts rather than publishing a
  universal distance or timeless relation score.
- Implement query-compiled indexed A-star and declared best-first search over typed
  states, with bulk frontier providers, goal and terminal predicates, contextual cost,
  provable heuristic contracts, canonical duplicate/reopen/tie behavior, exact
  completion certificates, and cost-model evidence. Metric top-k instructions may
  generate candidates but cannot define cognition-wide relevance.
- Make search names match executed priority semantics, retain depth and every other
  completion resource in state dominance, execute requested path multiplicity, expand
  frontier states through set-oriented server operations, and preserve complete typed
  transition receipts rather than target-plus-scalar-cost rows.
- Implement typed relation incidence and transport laws, dependence-aware evidence
  metrics, generated matrix-free operator applications, boundary/source compilation,
  and independently certified field solvers.
- Implement the typed relation, boundary, motif, contradiction, innovation, and
  counterfactual defect calculus without using numerical solver residual as frayed
  structure.
- Implement separate fast cognition, evidence-learning, and Gödel discovery loops.
  Gödel discovery classifies constrained vacancies, predicts occupant signatures,
  proposes facts, relation families, motifs, laws, operators, firmware operations, or
  cognition programs, partitions fitting/evaluation/counterexample evidence, executes
  experiments through OODA, and versions accepted calculus extensions without
  self-corroboration.
- Implement Observe, Orient, Decide, Act, and consequence observation as explicit typed

- Implement logical cognition programs, measured physical-plan selection, deterministic

- Implement and behaviorally cover the full request compiler inventory. Requests over

  definitional operation or caller-selected read catalog cannot certify the compiler.
- Implement spectral AImap generation as a modular derived perfcache with sparse block
  eigensolvers, reorthogonalization, gauge-invariant comparison, anchor alignment,
  incremental updates, complete recalculation probes, and coherent epoch publication.
- Implement persistent sessions as substrate state, including active propositions,
  unresolved questions, corrections, ellipsis, referents, cross-modal artifacts,
  rejected interpretations, and prior program receipts rather than only topic recency.
- Implement corrections, references, artifacts, tool activity, and prior-result access.

- Implement multilingual and cross-modal conversation.
- Implement modality-typed exact realizers over semantic acts without an English token
