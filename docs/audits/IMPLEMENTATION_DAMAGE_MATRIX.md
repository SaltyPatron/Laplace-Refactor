# Implementation damage matrix

Date: 2026-08-24

## Reading this matrix

This matrix correlates direct product requirements with read-only observations of the
preserved repository, Git history, live database, installed product tree, and session
records. It does not select historical code for reuse.

The status terms mean:

- **contradiction** — observed behavior conflicts with a direct invariant;
- **bypass** — the intended mechanism exists locally but product paths do not use it;
- **fragmentation** — multiple surfaces own semantics that require one engine contract;
- **activation defect** — source, built artifact, installed artifact, and running object
  cannot be proven identical;
- **proof gap** — a claim or local test exists, but complete product behavior has not
  been demonstrated.

## Result

The observed repository is not a stable base for product implementation. It is a rich
corpus of defect classes, partial mechanisms, repairs, counterexamples, and measured
failure modes. The new repository uses that corpus to construct deliberate broken
implementations and product acceptance tests. It does not inherit the old semantic
owners, file topology, schema, packaging, or completion signals.
