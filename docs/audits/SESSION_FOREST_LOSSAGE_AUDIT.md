## Evidence authority

The 190 messages are not one undifferentiated requirement source.

1. Direct inventor requirements and corrections establish product intent.
2. Inventor-supplied artifacts and measurements can establish facts after
   verification.
3. Pasted ChatGPT or agent review is contextual analysis and a source of leads. It
   does not become invention authority because it appears in a human message.
4. Assistant hypotheses, plans, summaries, and claims are not completion evidence.
5. Historical implementations establish continuity, demonstrated behavior, defects,
   and negative controls. They do not define the clean implementation.

This distinction prevents both post-hoc adoption of attractive review prose and loss
of a later direct correction.

## The forest

Laplace cannot be reduced to the current ISA, Unicode, PostgreSQL, perfcache, A-star,
the Goedel engine, a model compiler, or any other individual tree. Its stable whole is:

1. **One canonical universe.** Exact content identity, physical realization,
   occurrence, testimony, calculation, inference, standing, and referential identity
   remain distinct across every modality.
2. **One executable substrate.** C/C++ and PostgreSQL server integration own semantic
   calculation. SQL and C# orchestrate one typed, versioned, vector-first execution
   system. No adapter has private semantics.
3. **Exact structure before claims.** Merkle composition and typed physicality
   trajectories calculate containment, order, multiplicity, ancestry, geometry, and
   scoped co-occurrence. The 212-bit four-binary64 carrier is an intentional exact
   indexed transport, not an embedding or ordinary floating-point coordinate.
4. **Canonical state, compiled physical planes.** Perfcaches, indexes, AImaps,
   embeddings, tensors, and model artifacts are typed generated accelerations or
   projections. They remain subordinate, recipe-bound, and reproducible.
5. **Problem-relative cognition.** A goal compiles typed operands, bindings, scopes,
   obligations, authority, resources, and knowledge deficits. Query-relative
   operators and indexed bulk search select a semantic act; neither lookup nor one
   permanent similarity defines relevance or completion.
6. **Evidence and discovery without self-certification.** False and competing claims
   remain addressable. Dependence-aware immutable epochs calculate standing. Persistent
   typed incompleteness can generate falsifiable extensions through held-out evidence,
   counterexamples, experiments, OODA, and versioned calculus activation.
7. **Symmetric ingress and egress.** Models and external systems enter as attributable
   witnesses. Laplace can calculate consumer-specific representations and target
   artifacts, but successful shape, loading, or fluency cannot substitute for
   calculated behavior and independent verification.
8. **One activated product.** Build, dependency, database, service, package,
   performance, security, and release evidence are part of Laplace. A collection of
   green component tests is not the complete product.

The 12-stage operational graph is the executable ordering of these laws. Minimal
trusted source acquisition and package construction precede the product execution
framework; framework-mediated dependency activation follows both:

```text
minimal trusted acquisition and package construction
  -> universal execution framework and dependency activation
  -> Unicode root
  -> composition and physicality
  -> bulk canonical deposition
  -> evidence and referential adjudication
  -> guidance, operators, query, and search
  -> semantic acts, realization, and effects
  -> learning, Goedel discovery, and OODA
  -> model witness ingestion and target generation
  -> complete product activation
```

## Anti-loss mechanism

Issue #23 is the whole-product parent. The phase milestones mirror
`docs/product/WORK_PROGRAM.md`; stage issues mirror
`contracts/operation-model.json`. A new implementation PR is admitted only when it
names its operational stages, prerequisite stages, authoritative inputs, generated
state, persistence/acceleration roles, semantic owner, batch/resource/failure rules,
positive acceptance, and deliberate defect.

Requirements validation rejects a missing product-to-stage mapping, a cyclic operation
graph, a stage without a phase or issue, an undeclared issue reference, and a tracked
issue without an operational owner. GitHub therefore mirrors the machine-readable
roadmap instead of becoming a second disconnected one.
