# Laplace operational model

This document is the whole-product execution spine. The constitution defines what
Laplace is; this model defines how the parts execute together. A component, opcode,
cache, schema, query, model, or user interface is not Laplace independently and cannot
claim completion outside this spine.

## 1. One machine, several execution rates

Laplace preserves one universal canonical state and calculates the representation,
operator, search, artifact, or realization required by the current program.

```text
admit exact sources and recipes
  -> calculate canonical values and physicalities
  -> deposit immutable canonical and witnessed state
  -> publish complete derived epochs and acceleration planes
  -> compile a typed goal and completion contract
  -> calculate/query/search over exact and derived state
  -> select a complete semantic act
  -> realize or execute the act
  -> observe the consequence
  -> deposit learning or propose a falsifiable calculus extension
```

The fast cognition, evidence-learning, and Goedel discovery loops share this state but
have different mutation authority. Fast cognition cannot rewrite testimony or the
calculus. Learning publishes a new evidence/adjudication epoch. Discovery can only
propose a versioned extension until external evidence and activation gates accept it.

## 2. Framework before modules

Every product module executes through the same framework:

1. a generated typed value and instruction registry;
2. an immutable execution context naming source, identity, geometry, evidence,
   firmware, dependency, database, and perfcache epochs;
3. complete-program validation, authority checks, resource estimation, and effect
   admission before output or durable mutation;
4. a canonical vector/set/run batch representation;
5. a decomposer/calculation pipeline that emits typed batches once;
6. replaceable bulk sinks for canonical persistence, perfcache construction,
   observation/testimony deposition, derived-state construction, and result streams;
7. conserved topology-aware resource grants applied to native kernels, TBB, MKL,
   PostgreSQL, managed orchestration, and launched tools;
8. deterministic merge, cancellation, replay, progress, and receipt behavior;
9. generated C ABI, PostgreSQL, SQL, and C# bindings over the same operations; and
10. diagnostics that identify every loaded object, source, recipe, epoch, plan,
    artifact, database boundary, and result.

Modules supply typed codecs, validators, kernels, persistence schemas, perfcache access
laws, and semantic parity checks. They do not create another dispatcher, batching
loop, scheduler, receipt system, lifecycle, identity law, or persistence engine.

## 3. Self-hosting Unicode root

Unicode establishes the universal atom floor through a staged bootstrap:

```text
pinned Unicode 17 UCD + DUCET + conformance inputs
  + pinned identity grammar
  + pinned geometry and numeric recipe
  -> one native Unicode decomposer calculation
  -> one canonical ordered Tier-0 record stream
  -> content-addressed bootstrap perfcache
  -> set-oriented canonical database deposition from those exact records
  -> complete database/artifact bit-parity verification
  -> prefaulted coherent epoch activation
```

The bootstrap artifact may exist before the database rows because Laplace uses its own
calculated root to establish the substrate. It is not independently authoritative.
The database and perfcache are sibling serializations of the same calculation, retain
the same source/recipe/stream receipts, and activate together. A stale artifact or a
second implementation that happens to use the same version label is rejected.

The record stream includes, under declared typed sections:

- the codepoint position and stable content identity;
- complete DUCET key and total-order rank;
- pinned UCD properties needed by normalization, segmentation, composition, and
  realization;
- deterministic Super-Fibonacci placement on the unit glome;
- Hopf base/fiber conformance values or complete reproducible derivation;
- the canonical four-component coordinate and its exact numeric recipe;
- the 4D Hilbert locality key; and
- normalization decomposition/composition and reverse-address structures.

The fixed population is all 1,114,112 Unicode codepoint positions. Its fixed size is
what keeps bounded Super-Fibonacci atom placement stable. Laplace Unicode Position
Encoding v1 permanently closes the identity preimage: scalar values use bytes
identical to standard UTF-8, while the same variable-width bit layout addresses the
surrogate positions without calling those non-text bytes UTF-8.

## 4. Identity, tier, composition, and physicality

Content identity is BLAKE3-128 over the declared canonical preimage. Source, role,
language, model, occurrence, interpretation, trust, time, and tier do not enter it.
Ordered child identities form composite identity. An empty value is distinct from
absence, and a one-child composition is the child.

Structural tier is a proven floor, not an identity component or semantic type.
`Hello` has one content identity when it is a word, a one-word utterance, or a complete
sentence. Those uses create physicality/occurrence roles and structural paths; they do
not mint tier-keyed copies of the entity.

Physicality is an immutable calculated realization under a recipe and epoch:

- Tier-0 atoms use DUCET-ranked Super-Fibonacci points on S3.
- The Hopf fibration and any 3D glome projection are calculated views over the
  canonical four-component point.
- Composite placement is the exact four-dimensional arithmetic centroid of immediate
  child points with multiplicity; its radius is retained and it is not normalized
  back onto S3.
- The universal trajectory carrier retains 212 exact bits as four controlled
  binary64 lanes. Payload type and recipe select the decoder; numeric proximity of
  the carrier values is not geometry.
- Composition trajectories decode identity, ordinal, run, tier, atom, and typed
  metadata. From those occurrences Laplace calculates containment, precedence,
  following, recurrence, ancestry, shape, dimensions, and scoped co-occurrence.

These exact structural relations are calculations, not attestations and not rows for
every possible pair.

## 5. Runtime ingestion and persistence

After the root epoch is active, every source follows one set-oriented path:

```text
exact source bytes and source receipt
  -> edge codec produces typed observations and exact structural units
  -> Tier-0 leaves resolve from the active atom plane without PostgreSQL crossings
  -> parents compose leaf-to-trunk in memory
  -> equal identities deduplicate across the whole working set
  -> trunk-to-leaf membership probes run as at most one set operation per tier
  -> novel entities, physicalities, compositions, and occurrences bulk-deposit
  -> source claims bulk-deposit as testimony with lineage
  -> expensive adjudication/materialization/perfcache work reconciles after the
     canonical source boundary closes
  -> a complete derived epoch publishes atomically
```

SQL owns transactions, schemas, constraints, partitions, set routing, indexes, and
plan-visible server orchestration. C# owns source/service lifecycle and transport.
C/C++ and PostgreSQL server integration own the calculation. Cursors, per-row client
calls, per-element SPI queries, recursive SQL used as the native execution engine, and
row-trigger cache maintenance violate this model.

Canonical persistence includes identities, physicalities, composition occurrences,
observed occurrences, testimony, lineage, epoch manifests, and receipts. Perfcaches,
indexes, statistics, AImaps, query scores, model tensors, and rendered content are
rebuildable generated state with declared consumers and loss receipts.

## 6. Perfcache and index lifecycle

Perfcache means a family of typed immutable acceleration modules, not one generic
sorted-record file. Dense direct-address, sparse ordered, reverse identity,
normalization span, adjacency, spatial, and domain-specific planes retain different
access laws behind one native lifecycle/registry foundation.

```text
complete source boundary
  -> set-wise generation
  -> integrity and canonical semantic parity
  -> durable content-addressed publication
  -> map, validate, and prefault next generation
  -> atomic registry epoch switch
  -> old readers finish on their pinned generation
  -> retire old mapping after the final reader drains
```

The PostgreSQL postmaster loads a stable control plane, not one permanent data image.
A standards or data-epoch refresh must not require a postmaster restart. The operating
system page cache, mapped immutable artifacts, background prefaulting, and epoch-pinned
reader handoff keep queries hot without coupling data synchronization to process
startup. Binary extension/server upgrades retain a separate package and rolling
activation lifecycle.

Indexes generate bounded candidates for declared workloads. B-tree, GIN, GiST, BRIN,
4D Hilbert, geometry, trajectory, and perfcache access paths never define truth,
meaning, relevance, or completion. Exact typed decoding verifies candidates.

## 7. Evidence, truth state, and referential identity

Entity, physicality, occurrence, testimony, calculation, derived inference,
adjudicated standing, and referential identity are different state classes.

- False, contradicted, and low-standing claims remain addressable with provenance.
- Repetition from one root is dependence, not independent evidence mass.
- Exact structural calculation is not a witness.
- External negative observation, calculated contradiction evidence, and derived
  refutation hypotheses retain different epistemic kinds.
- Equal name content never proves equal referent. Compatibility defects generate
  merge/split hypotheses without deleting source occurrences or rewriting prior
  referential epochs.
- Consensus is an immutable as-of epoch over an exact evidence/dependence boundary.

Standing may use Glicko-2, source trust, independent roots, prediction success,
contradiction, time, and context through a declared deterministic recipe. No single
scalar replaces the underlying evidence topology.

## 8. Query, guidance, cognition, and realization

An input is decomposed into exact substrate state before cognition compiles a guidance
state:

```text
goal + typed operands + bindings + scopes + authority + resources
  + completion obligations + typed knowledge deficits
```

The query program defines which exact structural, geometric, occurrence, semantic,
epistemic, time, and context channels constitute progress. It generates typed
transition families, costs, constraints, duplicate/reopen rules, and completion.
Indexes and metric top-k operations generate frontier batches. A-star or a declared
best-first solver explores typed states; it does not reduce state identity to one
entity or relevance to one permanent distance.

Cognition completes only when every semantic obligation is satisfied or returned as a
permitted typed unresolved result. It then produces a modality-independent semantic
act. A realizer calculates exact Unicode, image, audio, code, query, model, or control
content from that act. Fluent realization cannot upgrade epistemic standing.

Curiosity is a goal-relevant actionable typed knowledge deficit. It competes under
expected deficit reduction, information value, cost, evidence rules, resources, and
authority; unrelated novelty cannot hijack the active goal.

## 9. Learning, Goedel discovery, and OODA

Observation deposits exact structure, occurrences, and attributable testimony.
Learning publishes a new evidence/adjudication epoch. Persistent typed frays can
generate candidates for missing entities, physicalities, relations, relation families,
motifs, laws, operators, firmware operations, or cognition programs.

A candidate is fitted only on its allowed boundary, evaluated on unchanged withheld
evidence, and subjected to counterexample search and experiment. It remains a derived
hypothesis until external support satisfies activation. Earlier calculus versions
remain replayable. Laplace cannot independently corroborate its own ancestry.

OODA closes selected effects back into observation: observe exact state and claims;
orient by generating the problem-relative representation and deficits; decide through
isolated counterfactual acts; execute within a hashed authority envelope; observe the
actual consequence.

## 10. Model symmetry

A conventional model is exact content and an attributable witness. Laplace decomposes
containers, architecture, layers, heads/experts, tensors, cells, bytes, and recipes;
calculates induced behavior and gauge-invariant operators; and deposits attributable
observations without making the model authoritative.

In the other direction, declared substrate calculations can generate AImaps,
embeddings, indexes, Q/K/V/O and FFN tensors, rerankers, model vocabularies, GGUF, and
other target artifacts. Every projection declares lost distinctions. Requested shape,
rank cycling, padding, successful loading, or fluent output cannot substitute for
calculated behavior and independent target-runtime verification.

## 11. Whole-product completion rule

Laplace is accepted only as the complete activated package. Component tests establish
component facts. They do not establish product completion.

Every implementation change must identify:

- the operational stages it changes and every prerequisite stage;
- canonical inputs, outputs, persistence, generated state, and perfcache/index role;
- native owner and SQL/C# orchestration boundary;
- source, recipe, dependency, numeric, resource, epoch, and authority receipts;
- batch, concurrency, cancellation, replay, and failure behavior;
- positive acceptance and a deliberate defect that proves the acceptance can fail;
- current implementation status without promoting staged or partial work to product
  completion.

The machine-readable companion is `contracts/operation-model.json`. Requirement
trace validation must fail when a product requirement is absent from that operational
graph.

## 12. Program tracking

The same machine-readable graph binds every stage to its work-program phase and live
GitHub issue owners. Issue #23 is the forest-level parent. Closed issue #24 owns the
fixed-prefix content-bound physical-session audit and remains in the graph as its
durable evidence owner. The verifier rejects a stage without a phase or
issue, a tracked issue without an operational owner, an undeclared issue reference,
an unknown stage dependency, a dependency cycle, or an unmapped product requirement.

GitHub records execution status, discussion, PRs, and CI evidence. It does not replace
the constitution or operational contract. An issue closure is valid only when its
behavioral acceptance and required package/receipt evidence are present.
