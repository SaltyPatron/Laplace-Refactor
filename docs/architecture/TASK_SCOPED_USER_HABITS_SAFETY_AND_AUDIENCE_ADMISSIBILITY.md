# Task-scoped user habits, safety/effect admissibility, and audience realization

Status: inventor-direct architecture clarification, 2026-09-04. This record is additive to `PROMPT_TRUNK_COGNITIVE_MICROCYCLE_AND_PROCEDURAL_MEMORY.md`, `STRUCTURAL_GEOMETRY_SEMANTIC_WEB_AND_GODEL_HABITS.md`, `COGNITION_EXECUTION.md`, #18, #169, #182, and #218. It does not replace the testimony/standing, source-admission, or typed-search contracts.

## 1. Boundary being clarified

Laplace already has the machinery needed for this behavior:

- exact canonical prompt/content composition;
- independently witnessed user/session/turn/source occurrences;
- physicality trajectories, containment, gaps, recurrence, co-occurrence and precedence;
- S3/angular/geodesic, Fréchet, Hausdorff, Karcher/Hilbert and other typed structural calculations;
- semantic relations, senses/referents, discourse, attestations, source/witness trust, confidence, dependence and contradiction;
- persistent successful and failed cognition trajectories;
- typed matchup/outcome state and derived standing;
- Gödel-discovered reusable programs, firmware scheduling habits and later muscle-memory acceleration;
- configured safety/social-norm evidence sources.

The remaining law is not another inference architecture. It is the boundary among four uses of the state that already exists:

```text
current task / semantic obligations
user-scoped procedural history
safety/effect admissibility
audience/presentation scope
```

They interact in one cognition episode but they are not the same state and one cannot silently replace another.

## 2. The current task remains the primary completion obligation

A user prompt is first an exact witnessed observation and cognition root. Persistent history can help interpret and execute the request, but it does not authorize the processor to abandon the current task in favor of an unrelated narrative about the user.

The processor should ask, in effect:

```text
what semantic act is this current observation requesting?
what obligations remain unresolved?
which prior programs/habits are applicable to this exact state?
what evidence would discriminate remaining ambiguity?
```

It should not ask, by default:

```text
what unrelated latent trait can I infer about this person?
```

A user-specific workflow habit is evidence about a repeated **interaction procedure**. It is not automatically evidence about personality, diagnosis, emotional state, political identity, protected attributes, or another unrelated person-level claim.

If the task itself genuinely requires reasoning about user state, that is a separate typed cognition operation with its own evidence, authority and completion contract. It is not a side effect of procedural memory.

## 3. User-scoped procedural memory is ordinary witnessed state

The same canonical content identity is reused regardless of which user observed/produced it. User/principal/session/turn identity remains occurrence/context state around the canonical content.

Procedural memory may therefore retain a user/principal-scoped history such as:

```text
prompt/task observation
-> selected semantic act
-> selected program/skill
-> realization/effect
-> user continuation/correction/confirmation
-> later independent outcome
```

The state signature for a reusable habit may include, where relevant:

- principal/user scope;
- session/discourse/world/time scope;
- current semantic-act/goal family;
- unresolved obligation shape;
- language/realization scope;
- structural/grammar/AST/physicality motif;
- S3/angular/geodesic/Fréchet/Hausdorff/Karcher/Hilbert calculations;
- topic/subject only as one typed context component, never the root of cognition;
- bound/unresolved senses and referents;
- source/evidence/dependence boundary;
- prior confirmations, corrections, failures and counterexamples;
- current explicit instructions;
- resource cost and expected obligation reduction.

No one member of that signature is a magic intent classifier.

## 4. Japanese-translation habit fixture

Consider a user who repeatedly works with a subject/task family and previously chose Japanese translation.

A prior execution might have the witnessed shape:

```text
current task A
-> semantic act: transform/translate
-> target realization: Japanese
-> execution succeeds
-> user accepts/continues from translated result
```

Later:

```text
current task B
-> exact prompt/content differs
-> structural/trajectory geometry resembles earlier task family
-> discourse/semantic-act evidence makes the same transformation plausible
-> prior outcome history makes Japanese realization a useful candidate
```

The first useful learned behavior is not blind auto-translation. It can be a scoped clarification:

```text
You asked for this previously to be translated to Japanese. Did you want me to translate this as well?
```

That question is valuable because the system has used past experience to reduce the ambiguity of the **task at hand** rather than rediscovering every possible operation or inventing an unrelated interpretation.

If repeated independent return legs show that the same operation is consistently desired under the same valid state signature, firmware may schedule the proven translation skill earlier and eventually require less confirmation under a versioned habit policy.

The progression is therefore:

```text
first/uncertain recurrence
-> broad cognition + candidate habit
-> scoped confirmation where useful

repeated validated recurrence
-> habit proposed earlier
-> less exploration/confirmation

stable practiced recurrence
-> current preconditions still checked
-> proven skill may execute through a cheaper habit/muscle-memory path
```

A current explicit instruction always has higher relevance to the present semantic act than stale procedural history:

```text
"Do not translate this."
```

must prevent the Japanese habit from firing for that request and should become corrective outcome evidence for the applicable lane.

The correction does not prove that Japanese translation is globally bad, nor does one successful translation prove that the user globally wants Japanese.

## 5. Geometry discovers candidates; semantics and outcomes promote them

A recurring trajectory can have a very similar Fréchet curve, angular relation, AST/physicality shape or other geometric signature. That is exactly useful for finding candidate repeated procedures.

It is not sufficient to establish the procedure's meaning.

Required separation:

```text
structural/geometric resemblance
    -> candidate recurring trace family

semantic/discourse/evidence/outcome agreement
    -> candidate reusable program meaning

held-out + negative-control performance
    -> validated skill

repeated valid user/task outcomes
    -> user-scoped scheduling habit
```

Two tasks can be geometrically close and semantically different. Two tasks can be geometrically different across paraphrase/language/grammar and still justify the same semantic program.

The system needs both negative controls:

- Fréchet-close / semantic-different must remain different;
- structural-different / semantic-same must be able to converge on the same learned operation when the evidence justifies it.

This is why procedural memory cannot be `same topic => same transformation` or a nearest-neighbor lookup over prompts.

## 6. Habit outcomes are typed return legs, not global preference scores

When Laplace proposes a learned operation, subsequent user behavior can create a real outcome event for that exact lane.

Example:

```text
Laplace asks whether to translate this similar task to Japanese

user confirms
    -> positive return leg for this user/task/semantic-act/context habit

user declines
    -> negative/corrective return leg for this lane

user says "not this one; keep future ones in Japanese"
    -> current-task negative/correction + broader explicitly witnessed preference state

user changes the entire task
    -> changed-precondition evidence, not necessarily a loss for the translation skill
```

The complete matchup/event remains more informative than one rating. Glicko-2 may be a derived human-readable standing for a declared outcome-bearing lane, but it is not the native inference mechanism and it does not replace the exact return-leg history.

## 7. Safety/effect admissibility is independent of firmware and habit

Safety is not a personality firmware and not a learned convenience preference.

Every path that can produce an external effect or governed realization must reach the same active safety/effect admissibility contract regardless of how the candidate semantic act was selected.

That includes:

- default/mainstream firmware;
- creative firmware;
- coding/domain/game firmware;
- a user-specific learned habit;
- a Gödel-discovered skill;
- a compiled muscle-memory fast path;
- a conventional-model-derived proposal;
- Conversation, MCP, OpenAI-compatible, native, PostgreSQL or another public/internal route.

Representative execution:

```text
OBSERVE exact prompt + persistent state
-> infer current semantic act / obligations
-> select candidate skill/habit/program
-> calculate candidate act/effect
-> calculate safety/effect obligations under active authority/evidence
-> calculate audience/presentation obligations
-> admit or reject/reroute the effect
-> REALIZE/EFFECT permitted act
-> WITNESS full receipt + outcome
```

A habit can make a permitted operation cheaper or more likely to be proposed. It cannot make a prohibited effect admissible.

A high rating/standing cannot make a prohibited effect admissible.

A fast path that skips safety/audience obligations is not semantically equivalent to the primitive path and therefore cannot qualify as muscle memory.

## 8. Harmful content is still content

Safety does not require corrupting the substrate.

An unsafe, hateful, sexual, violent, threatening, self-harm-related, or otherwise sensitive prompt remains an exact witnessed observation. Source material containing such content remains exact witnessed source material.

The machine can still need to:

- identify it;
- quote it where the selected permitted act requires exact quotation;
- classify it;
- compare it;
- explain why it matches or does not match a safety category;
- distinguish endorsement from reporting;
- distinguish instruction from prevention/research;
- distinguish hate from counter-speech or negation;
- retain provenance, context and disagreement.

The restriction belongs to the **semantic act/effect and realization obligation**, not to whether the underlying Unicode composition is allowed to exist in Laplace.

For a request whose requested effect would materially enable a prohibited harmful action, the prompt can still be observed and reasoned over while the enabling effect is not admitted. The resulting response should remain as close as possible to the user's actual permitted task rather than automatically replacing the conversation with unrelated psychological interpretation.

## 9. Safety/social-norm datasets are evidence, not one magic moderation score

The configured source estate under #195 deliberately contains distinct witnesses such as HateCheck, SGHateCheck, XSTest, Civil Comments, ToxiGen, Measuring Hate Speech, Social Bias Frames, ProsocialDialog, Social Chemistry 101 and RealToxicityPrompts.

The old source-estate work in `SaltyPatron/Laplace#1473` already records critical distinctions:

- harmful assertion/intent/behavior can carry negative normative evidence;
- identity/group mentions remain neutral;
- counter-speech, negated hate, reclaimed slurs, quotations, reporting and fictional speech retain context;
- continuous labels stay continuous;
- annotator disagreement remains state;
- model-generated and human-written/annotated evidence retain separate provenance;
- a bad-word lexicon is insufficient.

Those distinctions must survive inference.

Do not flatten them into:

```text
toxicity = 0.83
```

and then pretend that scalar answers every safety question.

A source annotation is also not timeless product policy. Sources provide witnessed evidence/contrast examples/limitations. A versioned active authority/policy declares which effect classes are admissible and what obligations must be calculated before effect.

The source roster must not be overclaimed. Hate/toxicity corpora do not automatically prove self-harm, weapons, sexual safety, child safety or another distinct effect class. Each required safety dimension needs its own admitted evidence/calculation/authority boundary and fixtures, or the machine must return an explicit incomplete/unsupported safety boundary.

## 10. Audience-appropriate realization is not source censorship

Knowledge admission and presentation are different operations.

A source such as ConceptNet can contain coarse, sexual, violent or otherwise audience-sensitive raw relations/surface forms. The user's cited example, `sport fucking`, illustrates the problem: even when such a relation is legitimately present in the admitted source, it does not follow that every realization should surface that wording to every audience.

The substrate should retain:

```text
exact source content
source identity/release
occurrence/physicality
relation/roles
witness/provenance/trust/confidence
```

A realization program additionally receives an audience/presentation scope.

For an explicitly declared child-safe or otherwise restricted audience, the realizer may:

- choose a non-explicit synonym/paraphrase when semantic obligations permit;
- omit an irrelevant explicit example;
- summarize the relation at an appropriate register;
- return a typed why-not when exact explicit rendering is necessary but disallowed.

For an allowed research, debugging, provenance or adult context, the exact source relation can remain inspectable.

The source fact does not change because the audience changed.

Audience scope must itself be bound from explicit request, account/product/guardian/authority state or another admitted source. The system must not infer that a user is a child merely from writing style, vocabulary or a procedural habit.

## 11. Safety and audience state remain inspectable

A complete conversation receipt should make it possible to distinguish at least:

```text
prompt trunk / occurrence
current semantic act and unresolved obligations
selected prior user/task habit, if any
habit evidence and counterexamples used
selected skill/program identity
structural/geometric proposal evidence
semantic/discourse evidence
candidate result/effect
safety obligation set + authority epoch
typed safety evidence/providers consulted
coverage gaps / unsupported dimensions
audience/presentation scope + authority
final admitted semantic act/effect
realization identity
why-not / reroute reason if applicable
subsequent observed outcome / correction
```

This is necessary both for debugging and for Gödel learning: the system needs to know whether an outcome reflects a bad semantic program, a bad habit trigger, a safety-classification error, a changed authority epoch, an audience-realization error, or an unrelated user correction.

Do not flatten all of those into one win/loss or confidence value.

## 12. Required acceptance

A conforming implementation proves at minimum:

1. repeated accepted Japanese translations for one user/task family can cause the proven translation skill to be scheduled earlier;
2. an uncertain recurrence can produce the scoped `You asked for this previously...` clarification;
3. a current explicit `do not translate` instruction overrides prior habit state;
4. Fréchet-close/structurally close but semantically different work does not inherit the transformation;
5. structurally different but semantically equivalent work can reuse the skill when semantic evidence justifies it;
6. task-scoped history does not silently widen into an unrelated personality/mental-state label;
7. incidental negative/emotional wording in an otherwise permitted task does not automatically replace the current task with psychological commentary;
8. every firmware/public route/fast path reaches the same safety/effect admissibility program;
9. a deliberate learned-habit or muscle-memory safety bypass fails;
10. quotation, research, negated hate, counter-speech, reporting and fictional speech remain distinguishable from endorsement/instruction;
11. identity/group terms alone do not acquire negative standing;
12. a missing safety dimension produces explicit incomplete/unsupported coverage rather than reuse of a generic toxicity scalar;
13. audience scope changes realization without rewriting/deleting the underlying source content;
14. an explicit child-safe realization can avoid unnecessary explicit source wording while an allowed research/provenance read can still inspect the exact source relation;
15. vocabulary/style alone cannot bind child status;
16. all receipts preserve current-task, habit, safety and audience state separately.

## 13. Deliberate defects

Reject:

- `same topic => translate to Japanese`;
- one successful prior user choice becoming a permanent global preference;
- geometric proximity promoted directly to semantic intent;
- a learned workflow habit stored as a personality/diagnosis/mental-state claim;
- a user preference or high standing overriding the current explicit instruction;
- a `safe` firmware that another firmware can bypass;
- safety only at the UI/HTTP layer;
- a muscle-memory fast path that skips admissibility checks;
- token/word blacklist moderation as the semantic safety model;
- identity/group vocabulary assigned intrinsic negative standing;
- all safety datasets flattened into one toxicity scalar;
- hate/toxicity data used to claim unrelated safety coverage;
- source knowledge deleted or altered merely because one audience should not see its raw form;
- inferred child status from language style;
- generic safety/psychological commentary replacing an otherwise permitted current task when no safety obligation requires the diversion.
